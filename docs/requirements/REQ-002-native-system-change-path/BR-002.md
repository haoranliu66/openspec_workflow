| 证据 | 来源 | 可信度 |

## 角色与约束

- 维护者需要减少不必要的 BR/PRD/FEATURE 重型治理，同时保留行为规格与关闭证据。
- AI 必须按变更性质而不是代码规模选择路径。
- OpenSpec 固定为 `1.5.0`；原生 Schema 可依赖该版本，但不得复制到本仓库形成漂移副本。
- system-change 仍遵守实施授权、稳定 Requirement ID、tasks/evidence/gates 和 archive 治理。

## 范围边界

- **范围内**：三路径选择、原生 spec-driven 接入、非产品 closeout、历史/Schema 识别、安装目标运行、文档与测试。
- **范围外**：修改 OpenSpec package、创建本地 `system-change` Schema、放宽 product-change 判断、取消 design/tasks、引入新的审批 artifact。

## 决策与假设

- `system-change` 是团队可读的路径名称，实际 `.openspec.yaml` 使用 `schema: spec-driven`。
- “规模不大”只作为辅助信号；产品目标、用户旅程、角色权限、业务规则、公共接口或显著数据/迁移风险优先决定走 product-change。
