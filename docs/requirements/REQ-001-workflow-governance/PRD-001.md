# PRD：change 授权停顿与精简关闭

> Acceptance IDs use the `PA-001` form and are unique within this file.

## 基本信息

- **需求 ID**：REQ-001
- **产品负责人 / 状态**：工作流维护者 / 已确认
- **业务目标 ID**：BG-001、BG-002、BG-003

## 用户与旅程

| 角色 | 当前痛点 | 目标旅程结果 |
|---|---|---|
| 工作流使用者 | AI 生成 tasks 后可能继续实施，缺少独立审阅授权点 | 先收到明确规划摘要，再在后续消息中授权具体 change |
| 交付维护者 | FEATURE 结果在本地 Markdown、JSON 和共享台账间重复维护 | 只在共享 FEATURE 维护逐条交付结论，closeout 只引用 evidence |
| 审查者 | 预检与正式关闭步骤容易被理解为两个强制入口 | 通过单个正式 close 命令完成校验、归档与索引更新 |

## 产品范围

- **范围内**：product-change 和 bugfix 的 Schema-aware 授权边界；保留 product-change 的本地 BR/PRD；移除新 product-change 的本地 FEATURE；共享 FEATURE 逐结果 evidence；直接替换现有 closeout 契约。
- **范围外**：持久化审批 artifact、审批服务、CI 授权证明、archive 重写。
- **依赖**：OpenSpec 1.5.0 的 artifact status、apply instructions、propose/continue/ff/apply/onboard skills 和现有 close workflow。

## 产品规则

- 原始开发请求、创建 change、生成 artifacts、`/opsx:continue` 或普通“继续”不构成实施授权。
- 授权必须发生在规划包生成完成后的后续用户消息，并绑定一个明确 change。
- `/opsx:apply <change>`、`确认实施 <change>`，或对只包含一个明确 change 的授权问题回复“确认”，均构成授权。
- 交付范围、行为、接口、数据、安全、迁移、回滚或任务边界发生实质修改后必须重新授权。
- 拼写、格式、链接、evidence 补录、task checkbox 和不改变范围的实现备注不使授权失效。
- 共享 FEATURE 只在证据存在时声明 `ready`；授权完成不等于交付完成或允许提前声明 ready。

## 结果级验收

| 验收 ID | 期望产品结果 | 证据方式 |
|---|---|---|
| PA-001 | AI 在 Schema 对应规划包完成后结束当前执行轮次，并展示明确 change 的计划摘要 | skill/治理规则测试与文档审查 |
| PA-002 | 只有规划完成后的明确用户消息才授权 apply，且实质规划修改使授权失效 | 授权场景测试 |
| PA-003 | product-change 保留 change-local BR/PRD，新 change 不再生成 local `feature.md` | Schema strict validation 与模板测试 |
| PA-004 | 共享 FEATURE 逐条保存 change、结果 ID、已交付结论、evidence IDs、版本和状态 | 共享 FEATURE parser/validator 测试 |
| PA-005 | product closeout 不再重复 PRD 路径、共享 FEATURE 路径或 FEATURE results，同时继续校验 Requirement/PRD、evidence 和四项门禁 | closeout contract 与集成测试 |
| PA-006 | `workflow close <change>` 是唯一必需的正式关闭入口；`validate:close <change>` 仅作为可选预检 | CLI/close workflow 测试与文档审查 |
| PA-007 | 已归档 change 的历史 `feature.md` 不被迁移或删除 | installer/upgrade 测试 |

> 本文不维护精确 WHEN/THEN 场景；可执行验收只在 OpenSpec capability spec 中维护。
