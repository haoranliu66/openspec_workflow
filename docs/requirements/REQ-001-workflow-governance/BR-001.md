## 角色与约束

- AI 负责创建规划 artifacts、展示摘要并在授权边界停止。
- 用户负责在规划完成后的后续消息中对明确 change 授权。
- 团队继续依靠协作治理授权真实性；Schema、脚本和 CI 不证明用户授权。
- product-change 继续维护 change-local `br.md` 与 `prd.md`，共享 BR/PRD/FEATURE 继续位于 `docs/requirements/`。
- 已归档 change 不因本次升级被改写或删除历史 `feature.md`。

## 范围边界

- **范围内**：apply 前授权停顿、授权失效条件、删除新 product change 的本地 FEATURE artifact、共享 FEATURE 结果/evidence 结构、直接替换现有 closeout 契约、关闭入口简化、相关安装说明和校验测试。
- **范围外**：通过签名、哈希、审批服务或 CI 证明用户授权；改写既有 archive；取消 Requirement/PRD、evidence 或四项适用门禁。

## 决策与假设

- `/opsx:apply <change>` 是用户在规划完成后的显式实施授权，不再重复询问。
- 仅格式、链接、evidence 补录和 task checkbox 更新不使授权失效。
- 共享 FEATURE 是已交付结论的唯一事实来源；closeout 只保存机器校验需要的 Requirement 映射、evidence 索引和门禁矩阵。
