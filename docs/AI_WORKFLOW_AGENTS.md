# AI 工作流权威与技能协作指引

本文件是安装器维护的 AI 治理指南。目标项目的根 `AGENTS.md` 应引用或合入这些规则；项目可以增加领域约束，但不得静默绕过本工作流的 change 交付生命周期。

## 适用范围与优先级

- 对代码、产品行为或系统行为的变更，本工作流是项目唯一的 change 交付生命周期：路径选择、OpenSpec artifacts、实施授权、验证、关闭审核与正式关闭都在本流程内完成。
- “唯一”不表示废除安全响应、发布、迁移、运维、代码评审、厂商工具或其他专项规则。系统、开发者、用户指令以及项目强制规则继续按其既有优先级生效。
- 其他 workflow 或 skill 只能作为当前 change 中的有界辅助步骤使用，不得创建并行的需求/实施/关闭生命周期，不得替代 OpenSpec artifacts，也不得绕过 change-scoped 授权。
- 若专项规则要求额外证据、审批或操作，应把它们纳入本 change 的 tasks、验证与团队审核，而不是另起一个相互竞争的交付流程。

## 上下文与技能加载

1. 先按项目根 `AGENTS.md` 与本工作流规定的顺序读取 `SPEC.md`、受影响规格、相关活动 changes 和必要历史。
2. 只在用户明确要求、平台规则触发或当前任务确有需要时读取对应 skill；不要预加载与任务无关的 skills。
3. 使用 skill 前明确它在当前 change 中承担的有界任务，例如调试、影响分析、代码评审或文档生成。
4. skill 输出属于辅助分析，不自动成为需求事实、实施授权、测试结果或关闭结论。

## 默认需求探索

- 当用户提出新增或实质修改代码、产品行为或系统行为的需求时，默认先采用 `/opsx:explore` 的只读思考姿态，再选择 bugfix、system-change 或 product-change，并创建或修改对应 change。
- 探索应快速检查 OpenSpec 活动上下文，读取相关 current specs 与必要代码，比较可行路线、风险和关键未知项。explore 中不得实施代码；它不是 artifact graph 节点，也不产生新的审批或程序门禁。
- 路线明确时，可以退出 explore 并在同一轮继续规划；完整规划包仍受既有实施授权停顿约束。关键未知项会改变路径、范围或风险时，先向用户展示结论与选项并等待决定。
- 问答、解释、阅读、状态查询、证据或非实质文案调整、明确的 apply/close/index/check/validate 命令，以及继续已经探索和规划的 change，不重复执行默认 explore。
- 某些 AI 平台不能直接调用 slash command；此时执行等价只读行为并如实说明，不得伪称 `/opsx:explore` 已被实际调用。

## 冲突处理

AI 发现其他 workflow、skill 或项目指引与本流程发生实质冲突时，必须及时向用户报告：

- 冲突来源与具体规则；
- 对当前 change、artifact graph、授权、验证或关闭的影响；
- 适用的指令优先级；
- 建议的兼容或取舍方案。

可以在不改变交付语义的前提下兼容时，将专项步骤纳入当前 change 后继续。无法按指令优先级消解，或不同选择会实质改变范围、风险或交付结果时，停止相关实施并等待用户决定。不得静默选择一条流程，也不得用 skill 的内部工作法覆盖本工作流治理。

## GitNexus 协作边界

GitNexus 是推荐但可选的代码理解工具，适合大型或陌生仓库中的架构探索、影响分析、调试与安全重构。

- 使用前先确认仓库上下文以及索引是否存在、是否新鲜；只有任务确有收益时才读取或更新索引。
- 按任务选择匹配能力：探索、影响分析、调试、重构或评审，而不是一次加载全部 GitNexus skills。
- GitNexus 不可用、未建立索引或结果不足时，回退到代码搜索、调用关系检查和测试，不得阻塞正常工作流。
- GitNexus 结果是辅助线索，不替代 canonical specs、源代码、测试、verification 或团队审核，也不构成 Schema、CI 或 formal close 门禁。

## 安装与项目所有权

- 安装器管理本文件以及根目录的 `AGENTS.ai-workflow.example.md`，升级时可更新它们。
- 如果目标项目没有根 `AGENTS.md`，首次安装会用合并样例创建一个项目自有的种子文件；该文件不会进入 `.ai-workflow.json` 的 `managedFiles`。
- 如果根 `AGENTS.md` 已存在，安装器始终原样保留，即使使用 `--force`；团队应审阅最新样例并人工合并适用规则。
- 嵌套目录中的 `AGENTS.md` 始终由目标项目拥有，安装器不会枚举、覆盖、备份或删除。
