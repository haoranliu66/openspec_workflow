# 项目 AI 交付治理

对代码、产品行为或系统行为的变更，先阅读并遵守 `docs/AI_WORKFLOW_AGENTS.md`。本工作流是项目唯一的 change 交付生命周期；其他 workflow 或 skill 只可作为该生命周期内按需加载的有界辅助，不得建立并行交付流程或绕过 change-scoped 实施与关闭授权。

用户提出新增或实质修改代码、产品行为或系统行为的需求时，默认先使用正确拼写的 `/opsx:explore`，或在平台不支持 slash command 时执行等价只读探索，再选择路径并规划 change。路线明确时可在同一轮继续规划；关键未知项影响路径、范围或风险时先等待用户决定。问答、状态查询、非实质文案调整、明确的 apply/close/维护命令和继续已规划 change 不重复 explore。explore 不是 artifact 或程序门禁，也不得在其中实施代码。

系统、开发者、用户指令以及本项目强制的安全、发布、迁移、运维和领域规则继续按其既有优先级生效。若其他 workflow、skill 或项目规则与本流程发生实质冲突，AI 必须说明冲突来源、影响、优先级和建议方案；无法消解时停止相关实施并等待用户决定。

GitNexus 推荐用于大型或陌生代码库的探索、影响分析、调试和重构。使用前检查仓库上下文与索引新鲜度，按任务加载匹配能力；不可用时回退到代码搜索与测试。其结果不替代 specs、代码、测试、verification 或团队审核，也不是 CI 或 formal close 门禁。
